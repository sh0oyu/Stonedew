# Plant rendering comparison — 0.2.9

A controlled client scene reproduces the reported regression: 24 mature plants in clay pots, six columns × four rows. The camera, field, saved appearance, FOV and window size remain fixed in the same saved test world. All 24 trays are visible in the steady measurement windows. The final test excludes dropped item entities.

| Measurement | 0.2.8 | 0.2.9 |
| --- | ---: | ---: |
| Reported steady FPS | 7–8 | 31 |
| Plant faces submitted/frame | 246,336 | 17,840 |
| Median plant submission CPU/frame | 50.2 ms | 4.38 ms |
| Typical 95th percentile CPU/frame | 62 ms | 5.1 ms |
| Maximum near plant mesh | 13,090 faces | 2,294 faces |

The measured field submits about **93% fewer plant faces**, with roughly **91% lower plant submission time** and about **4× the FPS**. Larger near plants and complete painted fans remain visible. Cached lighting replaces per-vertex light-strength work inside the face loop; compact flower/leaf geometry and earlier distant detail supply the main reduction. Tent models use ordinary static chunk rendering.

Conditions: Minecraft Java 1.21.1, NeoForge 21.1.264, Java 21, Xvfb/Mesa software rendering (`LIBGL_ALWAYS_SOFTWARE=1`), 854×480 game viewport, FOV 70, render distance 12 chunks, FPS cap 120, mip level 4. Camera foot position `(205.5, -57.5, 214)`, yaw 0°, pitch 18°. Final full near geometry is 2,294 faces; distant geometry is 106 faces from ten blocks onward.

The opt-in `-Dstonedew.profileRender=true` profiler measures CPU time inside actual tray rendering and samples reported client FPS in ten-second windows. It remains disabled in ordinary play. [Raw samples](0.2.9-render-profile.json) preserve each window. This is a controlled local result on a software renderer; other hardware, shader packs, multiplayer and the 500-plant target require their own measurements.
